# Biohub — Cell Tracking During Development

Решение соревнования [Biohub – Cell Tracking During Development](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development) на Kaggle.
**Бронзовая медаль**, public LB **0.955**.

Ноутбук: `biohub.ipynb`.

## Задача

По 3D-видео с флуоресцентного микроскопа нужно отследить клетки эмбриона данио-рерио во времени:

- найти клетки на каждом кадре;
- связать их между соседними кадрами;
- найти деления;
- восстановить родословные клеток.

Разметка разреженная: размечена только часть клеток. Метрика:

```
score = adjusted_edge_jaccard + 0.1 · division_jaccard
```

- `edge_jaccard` — доля верных связей между кадрами. Узлы сопоставляются с разметкой в радиусе 7 µm.
- Поправка `adjusted` штрафует за число предсказанных узлов сверх оценки реального числа клеток, с коэффициентом 0.1.
- `division_jaccard` считается по локальному окну вокруг каждого деления.

Ограничения code-соревнования: ноутбук без интернета, до 12 часов на GPU, пересчёт на закрытом тесте.

## Пайплайн

### 1. Детекция

- `TemporalUNet3D` — 3D U-Net с временным вниманием по окну кадров, предсказывает карту центров клеток.
- TTA на 8 видов: отражения, повороты на 90° и транспонирования в плоскости XY.
- Ансамбль двух независимо обученных моделей (два сида): карты детекции смешиваются с весом 0.8 для второй модели. Если смешанная карта теряет больше 10% кандидатов, на этом кадре остаётся карта основной модели.
- Порог детекции **0.960**.
- Голова уточнения координат (V1284) по признакам U-Net сдвигает центры клеток ближе к истинным.

### 2. Оценка связей

- Node-transformer оценивает вероятность связи для каждой пары клеток на соседних кадрах.
- Прямое и обратное направление времени сливаются через гармоническое среднее (вес обратного 0.15).
- TTA применяется и к признакам для связей. Вторая модель подмешивается там, где основная не уверена (`low_margin_consensus`).

### 3. Сборка треков (ILP)

Глобальная оптимизация через `tracksdata` + SCIP:

| Компонент | Вес |
|---|---|
| ребро | −1 · вероятность |
| появление трека | 0 |
| исчезновение трека | 2 |
| деление | 1.2 |

Лимит решателя — 1200 с на видео.

### 4. Постобработка

1. **Пересвязывание по движению.** Связи между кадрами пересобираются венгерским алгоритмом. Положение клетки на следующем кадре предсказывается по медианному смещению 12 соседних уверенных пар, в радиусе 40 µm. Работают два порога: 7 µm и 10 µm. Связи, выбранные ILP, получают бонус к стоимости.
2. **Возврат отброшенных детекций.** Пики детектора, которые отбросил ILP, возвращаются, если лежат ближе 4 µm к открытому концу или началу трека.
3. **Закрытие разрывов:**
   - пропуск в один кадр закрывается синтетической точкой. Её положение уточняется по интенсивности, а при длинном прыжке её должна подтвердить отдельная сеть центров (DeepCenter UNet3D);
   - пропуск в два кадра закрывается со строгими геометрическими условиями;
   - пропуски до трёх кадров заполняются по подпороговым пикам детектора.
4. **Восстановление делений.** Вторая дочь ищется среди начал треков рядом с родителем. Учитываются геометрия, симметрия сестёр, расхождение дочерей на следующем кадре и взаимная ближайшесть. Кандидата должна подтвердить сеть DeepCenter с порогом 0.15. Доля делений ограничена: на кадр и на видео.
5. **Фильтр коротких треков.** Компоненты короче 6 узлов удаляются, кроме компонент с делением. Короткие треки с высокой уверенностью связей частично сохраняются.
6. **Сглаживание координат.** Линейная аппроксимация по окну ±2 кадра внутри треков, с весом 0.8.

### 5. Локальная валидация

Перед финальной записью пайплайн прогоняется на 8 отложенных видео из train. Оценка ведётся по формуле официальной метрики. Набор параметров постобработки выбирается с защитой от переобучения: нужен минимальный прирост, и результат не должен проседать ни на одном типе эмбриона. В финальном решении так выбран порог DeepCenter для делений 0.15 (вместо 0.25).

## Что дало прирост

| Изменение | Public LB |
|---|---|
| исходная конфигурация | 0.953 |
| порог детекции 0.965 → 0.960 | **0.955** |

Главный вывод из разбора метрики: разметка разреженная, а штраф за лишние узлы слабый. Поэтому выгоднее находить больше клеток и закрывать разрывы, чем агрессивно чистить результат. Фильтрация слабых связей на тесте снижала скор, хотя на train-валидации выглядела улучшением.

## Запуск

Kaggle Notebook, GPU T4 ×2, интернет отключён. Нужные входные данные:

| Датасет | Содержимое |
|---|---|
| `biohub-cell-tracking-during-development` | данные соревнования |
| `biohub-tracking-support-pack-50ep-v1` | код инференса, основная модель, офлайн-зависимости |
| `biohub-temporal-unet3d-seed314159-v1` | вторая модель ансамбля |
| `biohub-deepcenter-unet3d-center-prior-v1` | сеть подтверждения центров |
| `biohub-v1284-head-s075` | голова уточнения координат |

При старте ноутбук проверяет SHA-256 кода и всех весов. Результат записывается в `submission.csv`.

Время на видимом тесте — около 1 ч 50 мин: из них инференс ~9 мин, остальное — постобработка, валидация и подбор параметров.

## Стек
